先运行无自研插件的官方主站，确认基础登录、菜单和用户管理，再通过后台上传后端 ZIP。上传后的 changed 提示符合宿主机制；页面上传未初始化表和菜单，因此在核对目标和用户授权后补做**仅插件**的建表与 seed，不再运行全站 init。

初始化采用 PostgreSQL 事务，只创建四张 app_update 表并执行匹配的标准 init 两次。检查原 74 条菜单、4 条角色菜单关联及 2 个用户保持不变，插件增加 15 条菜单/按钮，默认 demo 及两个渠道存在，重复 seed 未增加记录。没有执行 DROP 或全站初始化。

## 验证中发现并修复

1. 新宿主已移除旧 `backend.utils.limiter` 和 `pyrate_limiter` 依赖。增加插件限流适配层，优先使用 1.16 的 `backend.common.limiter.rate_limit('60/minute')`，旧宿主仍复用旧机制。缺实现或导入错误时不静默放行。
2. 干净前端未安装 Vue Test Utils。插件工作区自行声明开发依赖，只增加宿主锁文件中的插件 importer，不修改宿主根 package.json 或核心加载器。
3. 真实版本删除发现 `delete_model_by_column` 默认只允许单条，三产物触发错误。改为 `allow_multiple=True`，补真实 CRUDPlus + 临时 SQLite 回归；失败验证遗留的临时记录经正常 API 清理。

修复均同步回开发插件源码；未在测试主站补 Git 提交，也没有操作生产环境。
